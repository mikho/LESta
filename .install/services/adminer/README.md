# Adminer

A real, minimal (not phpMyAdmin — explicitly the provider's own choice, for a smaller footprint and attack surface) database admin tool for tenants to manage their own `TenantDatabase` (`tools.adminer.v1`), Tier 1 item #2 of the end-user feature parity survey.

Vendors the real upstream Adminer 6.1.1 (the MySQL-only, English-only single-file build — the smallest footprint Adminer ships) plus a first-party auto-login plugin (`adminer-lesta-login.php`), both checksum-verified against `manifest.json` before activation. Version updates ship via a manual per-node redeploy in v1 — bump the pinned version+sha256 here, commit, re-run `install.sh --apply` per node — the same process every other capability's own artifact already uses; there is no admin-triggered, fleet-wide push mechanism (one does not exist anywhere in this project yet, despite earlier backlog notes assuming otherwise).

Runs behind its own dedicated, static, node-wide PHP-FPM pool (`lesta-adminer` system identity, `open_basedir` scoped to its own deploy directory only, never a tenant's docroot) — never a tenant's own per-domain pool, since Adminer must reach any tenant's own database on this node while never being able to read any tenant's own files. Reached via a `/__lesta-adminer__` location on a tenant's own existing PHP+HTTPS-enabled domain (`web.nginx.v1`'s own conditional `AdminerSocket` field), never a new node-level vhost or TLS certificate of its own.

Login is a one-time, 60-second, single-use token minted by `App\Actions\TenantDatabases\PrepareAdminerSession` and redeemed by the vendored login plugin over a direct HTTPS call back to the control plane's own `/internal/adminer-credentials/{token}` endpoint — the one deliberate exception to "Laravel never touches a node directly" running in reverse (a node reading data from Laravel, not Laravel mutating a node), since nothing is provisioned or mutated by it. There is no Go dispatch package for this capability at all: this installer's own `--apply` *is* the entire install step, exactly like nginx/php-fpm/mariadb's own OS-level package installs — nothing is ever created/updated/deleted for it via the agent-mediated `OperationEnvelope` pipeline afterward, so no sudoers rule is needed either.
